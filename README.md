# メディア実験室

画像を音に、音声を画像に変換する React + TypeScript の単一ページアプリです。処理はブラウザ内で完結し、選択したファイルをサーバーへ送信しません。画面の「サンプルで試す」から、自分のファイルを選ばずに各経路を確認できます。

## 起動・ビルド・テスト

Node.js 20 以降と npm を用意してください。

```sh
npm install
npm run dev
```

表示されたローカルURLをブラウザで開きます。本番ビルドと自動テストは次のコマンドです。

```sh
npm run build
npm test
```

ビルド成果物は `dist/` に作られます。Bunを使う場合は `bun install` も可能です。`@breezystack/lamejs` の配布ライセンスは LGPL-3.0 です。
SHA-256計算には Web Crypto API を使うため、本番配信では HTTPS が必要です。ローカル開発の `localhost` は利用できます。

## 対応形式と上限

| 入力 | 出力 | 復元性 |
| --- | --- | --- |
| PNG・JPEG・WebP | mexp付きPCM16 WAV、MP3 | 専用WAVから、読み込み後のRGBA画素列を復元可能。MP3は非可逆 |
| PNG・JPEG・WebP | 4小節の音楽WAV、MP3 | 復元不可 |
| WAV・MP3 | 波形PNG、スペクトログラムPNG | 表示用。復元不可 |
| WAV・MP3 | データPNG、対応JSON | 両方から、デコード後のPCM16列を復元可能 |

- 入力ファイル: 最大100 MiB（画面上は100 MBと表記）
- 入力画像: 最大16,000,000画素
- 入力音声: 最大5分、モノラルまたはステレオ
- 展開後のPCM16: 最大64 MiB。5分の48 kHzステレオ音声はこの範囲に収まります。高サンプルレートでは時間上限より先にPCM容量の上限に達することがあります。
- データPNG: 最大24,000,000画素。入力画像とは別の上限です。
- 画像由来の音声と音楽: 44,100 Hz、モノラル

上限は [`src/lib/limits.ts`](src/lib/limits.ts) にまとめています。入力は無断で縮小しません。画像は可能な形式で寸法を先に調べ、音声はメタデータで長さを先に確認してからデコードします。端末のメモリ容量によっては、上限内でも大きなファイルの処理が難しい場合があります。

## 可逆性の範囲

画像の基準データは、ブラウザでデコードして `getImageData()` で確定した行優先RGBA8列です。透明画素のRGB値もこの列に含めます。生データWAVのPCM16バイト列はRGBA列そのもので、プレビュー用の音量調整やフェードはWAVに書き込みません。専用の `mexp` チャンクにバージョン、幅、高さ、バイト長、SHA-256を記録します。復元時はPCM16・モノラル・44,100 Hz、寸法、長さ、ハッシュを検証し、RGBA列を保持するPNGを独自に書き出します。

音声の基準データは、ブラウザの `decodeAudioData()` が返したデータをPCM16に確定した列です。デコード時にブラウザのAudioContextのサンプルレートへ再サンプリングされることがあります。各浮動小数点値を `[-1,1]` に制限し、負値には32768、非負値には32767を乗じて `Math.round()` します。チャンネルをフレームごとにインターリーブし、リトルエンディアンの16-bit値として保存します。

PCMピクセル画像はRGB8、アルファ不透明、余りを0で埋めたデータPNGです。対応JSONには形式バージョン、寸法、有効バイト長、サンプルレート、チャンネル数、フレーム数、SHA-256を記録します。復元処理はPNGのRGBバイトを直接解析し、キャンバスの色変換を経由しません。組み合わせ違い、改変、色変換後のPNGは検証に失敗します。

元のJPEG・PNG・WebP・WAV・MP3ファイルのバイト列そのものは復元対象ではありません。音楽生成、波形画像、スペクトログラム画像、MP3からの元データ復元も保証しません。画像由来のWAVの専用チャンク削除、音量変更、再サンプリングは復元対象外です。

## 操作

ファイルは画面へドラッグ＆ドロップできます。画像・音声を読み込み済みでも、対応ファイルをドロップすると差し替わります。往復実験のPCM経路では、データPNGと対応JSONを2ファイル同時に、または1つずつドロップできます。形式違い・複数ファイルの誤投入はエラーで知らせます。

画像タブでは、コピーしたPNG・JPEG・WebP画像を **Ctrl+V** で貼り付けられます。「クリップボードから貼り付け」ボタンも利用できます。ブラウザがボタンからのクリップボード読み取りを許可しない場合は、Ctrl+Vを使ってください。画像を読み込み済みでも貼り替えられます。

1. **画像 → 音**で画像を読み込み、「生データ音声化」または「音楽生成」を選びます。音楽生成は60〜180 BPMで調整できます。WAVを生成した後、必要な場合にMP3を別途エンコードして保存できます。大きな画像でもWAVの完成をMP3の処理待ちで遅らせません。生データ音声は自動再生せず、手動プレビュー時に低音量と短いフェードを適用します。長い生データ音声のプレビューは先頭10秒までです。保存WAVは全サンプルを保持します。
2. **音 → 画像**で音声を読み込み、波形・スペクトログラム・PCMピクセルを選びます。PCMピクセルではPNGとJSONを必ず一組で保存してください。WAVとMP3の内蔵サンプルもあります。
3. **往復実験**で保存したmexp付きWAV、またはデータPNGとJSONを選び、「復元して照合する」を押します。未選択なら同じ画面で生成済みのデータを使います。基準の画像・音声も読み込まれていれば差分バイト数を表示します。生成物内のSHA-256照合だけ成功し、比較基準がない場合は「完全一致」と表示しません。

処理中は進捗と中止操作を表示します。主要操作はボタンとファイル入力で行え、キーボードで操作できます。進捗・エラーは文字でも表示します。

## 実装

- `src/lib/wav.ts`: PCM16 RIFF/WAVEライター・パーサー、mexpチャンク
- `src/lib/png.ts`: RGB8/RGBA8 PNGのバイト単位の読み書き、CRC・フィルター処理
- `src/lib/imageInfo.ts`: PNG・JPEG・WebPのヘッダーから寸法を先読み
- `src/lib/pcm.ts`: 音声の量子化、PCMピクセル化、JSON照合
- `src/lib/music.ts`: 64列×8行の特徴量を使う決定的な4小節生成
- `src/lib/visualize.ts`: 波形、1024点Hann窓のSTFTスペクトログラム
- `src/lib/mp3.ts`: 交換可能なMP3エンコーダーインターフェース
- `src/worker.ts`: 変換処理用Web Worker
- `src/App.tsx`: ファイル検証、画面、再生、保存、往復実験

PNG圧縮には `fflate`、MP3エンコードには `@breezystack/lamejs` を使用します。MP3は録音APIに依存しません。

自動テストは透明画素と境界値、WAVのメタデータ欠落・改変、モノラル・ステレオPCM、PNG/JSON不一致、音楽生成の決定性とピーク、波形・スペクトログラム、MP3フレーム生成を検証します。

参考: [MDN decodeAudioData](https://developer.mozilla.org/en-US/docs/Web/API/BaseAudioContext/decodeAudioData)、[MDN Web Audio API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API)、[W3C PNG仕様](https://www.w3.org/TR/png-3/)
